# Local run, 2026-11-10

First end-to-end run of the full stack (`docker compose up -d --build`): one Kafka broker, PostgreSQL, Redis and the five services, driven by `device-simulator`. 500 simulated devices, 10 s heartbeats, about 48 events/s. One machine, everything on it.

## Unit tests

`./mvnw test`: 20 tests, 0 failures.

## Fixes needed to get it running

| Problem | Fix |
|---|---|
| `telemetry-processor` crashed at startup: its `ProcessorMetrics` bean had the same name as Spring Boot's own `processorMetrics` (CPU count) bean | Named the bean `telemetryProcessorMetrics` |
| A second simulator run reused `bootId=1, sequence=0..` for devices that already existed, so the pipeline (correctly) dropped every event as a duplicate and no device came back online | The simulator starts `bootId` from the run's start time, so each run looks like a reboot |
| The `clean` scenario still reported device faults | Fault reports scale with the scenario's fault factor (0 for `clean`) |

## Results

| Check | Result |
|---|---|
| Delivery, `silent-devices` scenario, 90 s | 4,137 acknowledged, 4,137 stored, 0 missing, 0 duplicates stored (40 deliberate duplicates and 21 malformed events sent) |
| Ingest latency (`received_at - device_time`) | p50 2.3 ms, p95 7.7 ms, p99 19.8 ms |
| Offline detection after heartbeats stop | All 500 devices marked OFFLINE within about 50 s (10 s heartbeat + 30 s grace + 10 s scan) |
| Back online after a reboot | Devices returned to ONLINE with cause REBOOT on the next run |
| Outage guard (FR-20): gateway stopped for 90 s under load | 0 devices marked offline during or after the outage. 11,016 events acknowledged, 11,016 stored, 0 lost (the simulator buffered and retried) |

## Reproduce

```
./mvnw -DskipTests package
docker compose up -d --build
mkdir -p target/ledger
SCENARIO=silent-devices DEVICES=500 DURATION=90s docker compose --profile sim run --rm device-simulator
# outage drill: start a 240 s clean run, then after 60 s:
docker compose stop ingestion-gateway   # wait 90 s
docker compose start ingestion-gateway
```
Compare `target/ledger/ack-ledger.csv` (device, bootId, sequence) against the `telemetry` table to count losses.
